# Career Growth — 职业发展与晋升

> **When to Use / 使用场景**: 规划职业晋升路径, 准备绩效评估, 争取升职加薪。

---

## Key Concepts / 核心概念

### 科技公司工程师级别体系

| 级别 | Google | Meta | Amazon | Apple | 典型年限 | 关键能力 |
|------|--------|------|--------|-------|---------|---------|
| Junior | L3 | E3 | L4 | ICT2 | 0-2 年 | 执行任务 |
| Mid | L4 | E4 | L5 | ICT3 | 2-5 年 | 独立负责 |
| Senior | L5 | E5 | L6 | ICT4 | 5-8 年 | 技术领导 |
| Staff | L6 | E6 | L7 | ICT5 | 8-12 年 | 跨团队影响 |
| Sr. Staff | L7 | E7 | L8 | ICT6 | 12+ 年 | 组织影响 |
| Principal | L8 | E8 | L9 | ICT7 | 15+ 年 | 公司影响 |

### 各级别核心差异

```
Junior → Mid:
  - 从 "需要指导" → "独立完成任务"
  - 能写好代码, 但需要人 review 设计

Mid → Senior:
  - 从 "完成任务" → "定义问题并解决"
  - 能做技术设计, 影响一个团队
  - 开始 mentor 初级工程师

Senior → Staff:
  - 从 "一个团队" → "多个团队"
  - 定义技术方向, 而不只是执行
  - 推动跨团队的技术改进

Staff → Principal:
  - 从 "多个团队" → "整个组织"
  - 影响公司的技术战略
  - 在行业中有影响力
```

## Step-by-Step Framework / 晋升准备框架

### 晋升包 (Promotion Packet) 准备

```
Step 1: 了解公司的晋升标准
    ↓
Step 2: 收集证据 (项目、影响、反馈)
    ↓
Step 3: 撰写晋升文档
    ↓
Step 4: 获得 sponsor 和支持者
    ↓
Step 5: 提交并参与评审
```

---

### Step 1: 了解晋升标准

```
□ 找到公司的 engineering ladder 文档
□ 了解下一级别的具体要求
□ 和 manager 讨论晋升路径
□ 找到下一级别的人, 观察他们在做什么
```

### Step 2: 收集证据

```
影响力证据维度:

技术影响:
  □ 核心项目的设计文档
  □ 技术决策的 trade-off 分析
  □ 性能优化数据
  □ 系统可靠性改进
  □ 代码质量提升

团队影响:
  □ Code review 质量和数量
  □ Mentor 的人的成长
  □ 技术分享/培训
  □ 招聘贡献 (面试官)
  □ 团队流程改进

跨团队影响:
  □ 跨团队项目领导
  □ 技术标准制定
  □ 共享工具/库的创建
  □ 跨团队协作的推动

业务影响:
  □ 用户指标改善
  □ 收入增长贡献
  □ 成本优化
  □ 用户体验改进
```

### Step 3: 撰写晋升文档

#### 晋升文档模板

```
═══════════════════════════════════════════
  Promotion Justification Document
  [当前级别] → [目标级别]
  [你的名字] | [日期]
═══════════════════════════════════════════

1. SUMMARY (摘要)
[2-3 句话总结你为什么应该被晋升]

2. CURRENT ROLE & IMPACT (当前角色和影响)
[描述你当前的角色和主要贡献]

3. EVIDENCE OF NEXT-LEVEL PERFORMANCE (下一级别表现的证据)

  3.1 Technical Impact (技术影响)
  ┌─────────────────────────────────────────────────┐
  │ Project: [项目名]                                │
  │ Role: [你的角色]                                 │
  │ Impact: [量化影响]                               │
  │ Evidence: [链接/数据/文档]                       │
  │ Meets Level Criteria: [对应哪条晋升标准]         │
  └─────────────────────────────────────────────────┘

  [重复 3-5 个项目]

  3.2 Team Impact (团队影响)
  [mentorship, hiring, process improvement]

  3.3 Cross-Team Impact (跨团队影响)
  [技术标准, 共享工具, 跨团队项目]

4. GROWTH AREAS (成长区域)
  [诚实地说你还需要成长的地方]
  [以及你计划如何改进]

5. SUPPORTING REFERENCES (支持者)
  - [同事 A]: "[具体评价]"
  - [同事 B]: "[具体评价]"
  - [其他团队的 Tech Lead]: "[评价]"
```

---

### Step 4: 获得 Sponsor

```
你需要:
1. Manager 的支持 (最重要)
   - 让 manager 知道你的晋升目标
   - 定期和 manager review 进展
   - 让 manager 帮你分配 high-visibility 的项目

2. 同级别的支持
   - 展示你的工作给同级别的 senior engineers
   - 在 code review 和 design review 中建立声誉

3. 跨团队 sponsor
   - 让其他团队的 lead 了解你的影响力
   - 跨团队项目是最好的方式
```

## 绩效评估策略

### Exceeds Expectations 达成超越期望

```
策略:
1. 理解 "期望" 是什么
   - 不只是完成任务, 而是超出预期
   - 不只是技术好, 还要有影响力

2. 做 "下一级别" 的工作
   - 最好的晋升方式就是已经在做下一级别的工作
   - "在当前级别待的时间不重要, 重要的是你已经在下一级别表现"

3. 量化一切
   - 不要说 "我提升了性能"
   - 要说 "我将 p99 延迟从 800ms 降低到 120ms"

4. 确保 manager 知道你的成就
   - 定期 1:1 更新
   - 写 weekly/monthly update
   - 不是炫耀, 是信息透明

5. 建立你的 "个人品牌"
   - 在团队中成为某领域的 go-to person
   - 写技术文档和 design docs
   - 做 tech talks
```

## Common Mistakes / 常见错误

1. **只埋头干活**: 做了好事不说, 没人知道
2. **等 manager 提晋升**: 你应该主动管理自己的职业
3. **只关注技术**: 晋升需要技术 + 影响力 + 沟通
4. **忽视 1:1**: 1:1 是最重要的沟通渠道
5. **不写文档**: design docs 是你的工作记录
6. **不做 mentorship**: 高级别必须影响他人
7. **不理解业务**: 技术要服务于业务
8. **太早/太晚谈晋升**: 太早显得不成熟, 太晚错过窗口
9. **不找 sponsor**: 没有人为你说话, 晋升很难
10. **一次失败就放弃**: 晋升有时需要多次尝试

## Pro Tips / 高手技巧

- **做 "glue work"**: 那些没人做但很重要的事情 (文档、流程、onboarding)
- **写 weekly update**: 每周给 manager 发 3-5 行进展更新
- **主动找 high-visibility 项目**: 新项目、跨团队项目、管理层关注的项目
- **建立技术影响力**: 写 RFC、做 tech talk、创建团队 wiki
- **理解公司的晋升节奏**: 大公司通常有固定的晋升周期
- **跳槽也是晋升**: 有时候外部机会比内部晋升更快
- **技术深度 vs 技术广度**: Senior 需要深度, Staff 需要广度 + 深度

## Practice / 练习清单

### 每月检查

```
□ 更新你的成就记录 (不要等到 review 时才回忆)
□ 和 manager 进行 career 1:1
□ 至少做一个超出当前角色的事情
□ 收集一个 peer feedback
□ 阅读一个下一级别的人的 design doc
```

### 每季度检查

```
□ 更新晋升文档 (如果有晋升目标)
□ Review career ladder mapping
□ 调整行动计划
□ 和 mentor/sponsor 交流进展
```
