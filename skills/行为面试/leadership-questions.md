# Leadership Questions — 领导力面试问题

> **When to Use / 使用场景**: 经理/总监级别的行为面试，考察领导力、团队管理和决策能力。

---

## Key Concepts / 核心概念

### 领导力评估维度

| 维度 | 英文 | 考察内容 |
|------|------|---------|
| 冲突解决 | Conflict Resolution | 如何处理团队内/跨团队冲突 |
| 团队建设 | Team Building | 如何组建、培养、留住人才 |
| 决策能力 | Decision Making | 如何在不确定中做出决策 |
| 授权委派 | Delegation | 如何分配任务、培养下属 |
| 影响力 | Influence | 如何在没有权威时推动事情 |
| 战略思维 | Strategic Thinking | 如何平衡短期和长期目标 |
| 变革管理 | Change Management | 如何推动组织变革 |
| 结果导向 | Results Orientation | 如何确保团队交付成果 |

---

## Step-by-Step Framework / 分步框架

### STAR-L 扩展框架

```
S (Situation)  — 情境: 背景和挑战
T (Task)       — 任务: 你的角色和职责
A (Action)     — 行动: 你具体做了什么
R (Result)     — 结果: 量化成果
L (Learning)   — 学习: 你从中学到了什么 (领导力问题加分项)
```

### 领导力回答框架

```
1. 展示 self-awareness (自我认知):
   "我意识到作为 leader, 我需要..."

2. 展示 empathy (同理心):
   "我理解 [stakeholder] 的顾虑是..."

3. 展示 decisiveness (果断):
   "在权衡了 [因素] 后, 我决定..."

4. 展示 accountability (责任担当):
   "最终结果由我负责, 因为..."

5. 展示 growth mindset (成长心态):
   "这次经历教会我..."
```

## Templates / 问题与回答模板

### 冲突解决

#### Q1: Tell me about a time you resolved a conflict within your team.

```
模板:
S: "两个工程师对 [技术方案] 有严重分歧, 导致 [影响]"
T: "作为技术负责人, 我需要在不影响进度的情况下解决分歧"
A: "我安排了三方会议:
    1. 先让双方各自陈述理由和数据支撑
    2. 引导大家聚焦在 [共同目标] 而非个人偏好
    3. 我提出了 [折中方案/实验方案], 让数据说话
    4. 设定了 [review 时间点], 根据结果决定最终方案"
R: "双方都认可了最终方案, 项目按时交付,
    团队后来建立了技术决策 RFC 流程"
L: "我学到了冲突往往源于信息不对称, 
    好的 leader 需要创造一个让不同声音被听到的环境"
```

#### Q2: How do you handle a team member who consistently underperforms?

```
模板:
S: "团队中有一位 [角色], 绩效持续低于预期, 具体表现: [例子]"
T: "我需要帮助他提升, 同时确保不影响团队整体产出"
A: "1. 安排了一对一, 用具体数据和例子说明问题 (非批评)
    2. 倾听他的困难: [缺乏技能/个人问题/动机不足]
    3. 共同制定了 PIP (绩效改进计划):
       - 明确期望和时间线
       - 提供 [培训/mentor/资源]
       - 每两周 check-in
    4. 同时做好 backup 计划, 确保项目不受影响"
R: "[X] 周后, 他的 [指标] 提升了 [百分比],
    6 个月后成为了团队的 [角色]"
L: "大多数 underperformance 不是能力问题, 而是匹配问题或支持不足"
```

#### Q3: Describe a time you had to manage a conflict between two teams.

```
模板:
S: "Team A 和 Team B 在 [接口/职责/资源] 上有冲突,
    导致 [项目延期/互相推诿]"
T: "我需要协调两个团队, 找到双方都能接受的方案"
A: "1. 分别与两个团队 lead 一对一了解诉求
    2. 识别真正的利益点 (通常不是表面上说的)
    3. 组织联合会议, 用数据和用户价值驱动讨论
    4. 推动建立 [SLA/RACI/接口文档]"
R: "冲突解决, [项目] 按时交付, 两个团队后来在 [其他项目] 中顺利合作"
```

### 团队建设

#### Q4: How do you build a high-performing team?

```
框架:
1. Hiring (招聘):
   - 明确 role requirements 和 culture fit
   - 结构化面试, 标准化评分
   - 多样性招聘

2. Onboarding (入职):
   - 30-60-90 天计划
   - Buddy 机制
   - 第一周就有小任务建立信心

3. Development (培养):
   - 定期 1:1, 不只是 status update
   - IDP (Individual Development Plan)
   - Tech Talk / 代码 Review / Pair Programming

4. Retention (留人):
   - 有意义的工作 + 成长机会
   - 及时认可和反馈
   - 有竞争力的薪酬和工作生活平衡

5. Culture (文化):
   - 心理安全感 (Psychological Safety)
   - 技术卓越文化
   - 透明沟通
```

#### Q5: Tell me about a time you had to let someone go.

```
模板:
S: "经过 [X 个月] 的绩效改进, [员工] 仍未达到期望"
T: "作为 manager, 我需要做出艰难决定, 同时保护团队和当事人"
A: "1. 确保 HR 参与, 流程合规
    2. 与员工坦诚沟通, 说明原因和下一步
    3. 提供 severance 和推荐信支持
    4. 与团队沟通 (不透露细节), 确保工作交接"
R: "团队理解并尊重这个决定, 整体士气未受影响,
    填补后的新人 [表现更好]"
L: "最难的领导力决定往往也是最重要的。拖延只会让问题更糟"
```

### 决策能力

#### Q6: Tell me about a difficult technical decision you had to make.

```
框架:
1. Context (背景):
   - 什么决策? 为什么难?
   - 有哪些选项?

2. Analysis (分析):
   - 每个选项的 pros/cons
   - 用数据支撑
   - 咨询了谁的意见

3. Decision (决策):
   - 选了什么? 为什么?
   - 有哪些风险? 如何缓解?

4. Outcome (结果):
   - 结果如何?
   - 如果重来, 会做不同的决定吗?
```

#### Q7: How do you make decisions with incomplete information?

```
框架:
1. 区分 "需要知道" vs "好知道":
   - 80/20 法则: 80% 的信息足以做 90% 的决策

2. 设定决策时间线:
   - 不是 "等更多信息", 而是 "在 X 时间前决定"

3. 可逆性评估:
   - 可逆决策: 快速决定, 边做边学
   - 不可逆决策: 多花时间, 多咨询

4. 小步试错:
   - MVP/原型验证假设
   - 设置 checkpoint 验证方向
```

### 授权委派

#### Q8: How do you delegate effectively?

```
框架:
1. 选对人:
   - 能力匹配 (不是最闲的人)
   - 成长机会 (给想发展的人)

2. 明确期望:
   - What: 做什么
   - Why: 为什么重要
   - When: 什么时候完成
   - How much: 自主度多高

3. 适当放权:
   - 不是 micromanage
   - 设定 check-in 频率而非随时监督

4. 提供支持:
   - 资源和信息
   - 去除障碍

5. 认可成果:
   - 公开表扬
   - 把功劳给执行者
```

### 影响力

#### Q9: Tell me about a time you influenced without authority.

```
模板:
S: "我需要推动 [变革/方案], 但 [受影响的人] 不向我汇报"
T: "我需要用影响力而非权力来推动"
A: "1. 建立 credibility: 用数据和 prototype 证明可行性
    2. 找到 champions: 先说服 1-2 个支持者
    3. 共创而非推销: 邀请对方参与方案设计
    4. 小范围试点: 用成功案例说服更多人"
R: "[X]% 的团队采纳了方案, [业务指标] 提升了 [百分比]"
```

### 变革管理

#### Q10: Tell me about a time you led a significant change.

```
框架:
1. Create urgency (创造紧迫感):
   - 为什么现在必须改变?
   - 不改变的代价是什么?

2. Build coalition (建立联盟):
   - 关键 stakeholder 是谁?
   - 谁是 early adopter?

3. Communicate vision (传达愿景):
   - 清晰的 "Why"
   - 人人可理解的语言

4. Quick wins (快速胜利):
   - 找到容易实现的改进
   - 用成功建立信心

5. Sustain (持续推动):
   - 制度化变更
   - 度量和反馈
```

## Common Mistakes / 常见错误

1. **只说 "我们" 不说 "我"**: 面试官想听你的贡献
2. **贬低前团队/下属**: 永远保持专业
3. **只讲成功不讲失败**: 展示你从失败中学习
4. **忽略人的维度**: 技术 leader 也要关心人
5. **过度 micromanage**: 展示你懂得放权
6. **不做 follow-up**: 强调你持续跟进和迭代
7. **回避艰难决定**: 面试官想看你如何 handle 难题
8. **缺乏数据支撑**: "团队效率提升" → "sprint velocity 从 40 提升到 65"

## Pro Tips / 高手技巧

- **不同级别侧重不同**:
  - Tech Lead: 技术决策 + 技术影响力
  - Engineering Manager: 团队建设 + 人员管理
  - Director+: 战略思维 + 组织变革
- **准备 "我的领导力哲学"**: 2-3 句话概括你的领导风格
- **展示 vulnerability**: 承认你的弱点和成长过程
- **用 metrics 量化**: 团队效率、离职率、交付质量
- **提及 1:1 方法论**: 定期沟通、IDP、反馈循环
- **讨论 psychological safety**: 这是当前最热门的领导力话题

## Practice / 练习清单

```
周一: 准备 2 个新故事
周三: 用 STAR-L 框架练习 3 个问题
周五: 和朋友 mock interview 30 分钟
```

### 必须准备的故事

```
□ 一个你推动的技术变革
□ 一个你处理的人事问题
□ 一个你做的艰难技术决策
□ 一个你培养的团队成员
□ 一个你处理的跨团队冲突
□ 一个你失败后重新站起来的经历
□ 一个你影响组织的故事
□ 一个你平衡多方利益的案例
```

> **领导力不是头衔，是行为。** 不管你的级别是什么，面试官想看到的是你如何思考、如何影响、如何在困难中做出决定。准备好你的故事，展示真实的自己。
>
> Leadership is not a title — it's a behavior. Show the interviewer how you think, influence, and make decisions under pressure.
