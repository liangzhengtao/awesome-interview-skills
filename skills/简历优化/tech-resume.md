# Tech Resume — 技术简历写作

> **When to Use / 使用场景**: 创建或更新技术简历，优化 ATS 通过率，量化技术成就。

---

## Key Concepts / 核心概念

### 简历评估标准

| 维度 | 权重 | 说明 |
|------|------|------|
| ATS 通过率 | ★★★★★ | 机器筛选关键词匹配 |
| 技术栈匹配 | ★★★★★ | 与 JD 的技术对齐 |
| 成就量化 | ★★★★☆ | 用数字证明影响力 |
| 排版清晰 | ★★★★☆ | 10 秒内能抓住重点 |
| 经历相关性 | ★★★★☆ | 与目标岗位的相关度 |

### ATS (Applicant Tracking System) 优化

```
ATS 工作原理:
1. 解析简历文本
2. 提取关键字段 (姓名、邮箱、技能、经历)
3. 与 JD 关键词匹配
4. 计算匹配度分数
5. 按分数排序，高分进人工筛选

优化策略:
✅ 使用标准标题 (Experience, Education, Skills)
✅ 使用 .docx 或 .pdf (看 JD 要求)
✅ 关键词自然融入 (不堆砌)
✅ 使用标准字体 (Arial, Calibri, Times)
✅ 避免表格、图片、图标、页眉页脚
✅ 用标准日期格式 (Jan 2023 - Present)
❌ 避免花哨排版、图标、图表
❌ 不要用两栏布局 (ATS 可能解析错乱)
```

## Step-by-Step Framework / 分步框架

### 简历结构 (按重要性排序)

```
1. Header (头部)
   - 姓名 (大号加粗)
   - 邮箱 | 电话 | LinkedIn | GitHub | 个人网站
   - 城市 (可选)

2. Summary (摘要) — 可选, 适合有经验者
   - 2-3 句话概括你的价值主张
   - 包含关键词

3. Experience (工作经历) — 最重要
   - 倒序排列
   - 公司 | 职位 | 时间 | 地点
   - 3-5 个 bullet points, 用 STAR 格式

4. Projects (项目) — 对应届生很重要
   - 项目名称 | 技术栈
   - 2-3 个 bullet points

5. Skills (技能)
   - 编程语言: Python, Java, Go, TypeScript
   - 框架: React, Spring Boot, FastAPI
   - 工具: Docker, Kubernetes, AWS
   - 数据库: PostgreSQL, Redis, MongoDB

6. Education (教育)
   - 学校 | 专业 | 学位 | 毕业时间
   - GPA (如果不错的话)
   - 相关课程 (应届生)
```

## Before & After / 修改前后对比

### Example 1: 模糊 → 量化

```
❌ BEFORE:
"Worked on the backend API and improved performance."

✅ AFTER:
"Optimized the user profile API by implementing Redis caching and
database query restructuring, reducing p99 latency from 800ms to 120ms
and decreasing database load by 65%, supporting 2M daily active users."
```

### Example 2: 被动 → 主动

```
❌ BEFORE:
"Was responsible for the deployment pipeline."

✅ AFTER:
"Designed and implemented a zero-downtime deployment pipeline using
GitHub Actions and Kubernetes rolling updates, reducing deployment
time from 45 minutes to 8 minutes and eliminating production incidents
caused by deployments (previously 2-3 per month)."
```

### Example 3: 列任务 → 说影响

```
❌ BEFORE:
"- Wrote unit tests
- Fixed bugs
- Participated in code reviews"

✅ AFTER:
"- Increased test coverage from 45% to 87% across 3 microservices,
   catching [X] bugs before production
- Resolved [X] critical production issues, maintaining 99.95% uptime
- Conducted [X]+ code reviews per sprint, establishing team coding
   standards adopted by [Y] engineers"
```

### Example 4: 技术 → 业务价值

```
❌ BEFORE:
"Migrated the database from MySQL to PostgreSQL."

✅ AFTER:
"Led the migration from MySQL to PostgreSQL for the orders service
(50M+ records), implementing data validation and rollback strategy.
Achieved zero-downtime migration, improved query performance by 40%,
and reduced infrastructure costs by $15K/month through better
connection pooling."
```

## Achievement Quantification / 成就量化公式

### 公式模板

```
[Action Verb] + [What You Did] + [Technology/Method] + [Quantified Result]

Action Verbs (按级别):
Junior: Built, Implemented, Fixed, Tested, Documented, Assisted
Mid:    Designed, Optimized, Led, Migrated, Automated, Delivered
Senior: Architected, Strategized, Scaled, Transformed, Mentored, Drove

量化维度:
- Performance: latency, throughput, response time
- Scale: users, requests, data volume
- Efficiency: time saved, cost reduced, automation
- Quality: uptime, bug reduction, test coverage
- Team: engineers mentored, processes improved, hires
- Business: revenue, conversion, retention, engagement
```

### 量化示例

| Before (模糊) | After (量化) |
|---------------|-------------|
| Improved performance | Reduced API latency by 70% (800ms → 240ms) |
| Worked on scaling | Scaled system from 10K to 500K concurrent users |
| Fixed bugs | Reduced production incidents by 80% (50 → 10 per month) |
| Mentored junior | Mentored 4 engineers, 2 promoted to mid-level within 12 months |
| Built a feature | Built checkout flow used by 2M+ monthly users, +15% conversion |
| Automated process | Automated deployment pipeline, saving 20 hours/week across team |
| Reduced costs | Optimized AWS infrastructure, saving $50K/month (30% reduction) |

## Keyword Strategy / 关键词策略

### 如何从 JD 提取关键词

```
Step 1: 找 3-5 个目标岗位的 JD
Step 2: 提取高频技术关键词
Step 3: 提取软技能关键词
Step 4: 自然融入简历

例:
JD: "Experience with distributed systems, microservices, and cloud
     infrastructure (AWS). Strong communication skills."

简历融入:
"Distributed Systems & Microservices:
• Designed distributed [system] using microservices architecture on AWS,
  handling [X]QPS across [Y] services with [Z]% uptime"
```

## Common Mistakes / 常见错误

1. **一页以上**: 大多数情况下控制在一页
2. **拼写/语法错误**: 一次错误就可能被淘汰
3. **不量化的成就**: "improved performance" 没有任何信息量
4. **堆砌关键词**: ATS 能检测到不自然的关键词堆砌
5. **用 "Responsible for"**: 用主动的 action verbs
6. **列任务而非成就**: "Fixed bugs" vs "Reduced production incidents by 80%"
7. **不针对 JD 定制**: 每个岗位都应该微调简历
8. **花哨排版**: 保持简洁专业
9. **不放 GitHub**: 技术简历必须有代码作品
10. **太长的工作描述**: 每份工作 3-5 个 bullet points

## Pro Tips / 高手技巧

- **X-Y-Z 公式** (Google 推荐): "Accomplished [X] as measured by [Y], by doing [Z]"
- **一页纸法则**: 每增加一年经验, 可以增加最多 0.5 页 (上限 2 页)
- **PDF 格式**: 除非 JD 明确要求 .docx
- **文件名**: FirstName_LastName_Resume.pdf
- **LinkedIn 同步**: 简历和 LinkedIn 内容要一致
- **找人 review**: 让行业朋友或专业 coach 帮你看
- **更新频率**: 每 3-6 个月更新一次, 及时记录新成就
- **A/B 测试**: 如果在求职, 尝试不同版本看哪个回复率高

## Practice / 练习清单

```
□ 从 JD 中提取 10 个关键词
□ 为每段经历写 3-5 个量化 bullet points
□ 检查所有 action verbs 是否够强
□ 检查是否有量化数字
□ 检查 ATS 兼容性 (纯文本能否正常显示)
□ 让 3 个朋友 review 并给反馈
□ 针对 3 个不同 JD 出 3 个版本
```
